# BoardMark 技术说明

面向部署、调参与二次开发。使用说明见 [README](../README.md)。

阅读对象：负责教室电脑维护的电教/多媒体运维人员，以及需要修改代码的开发者。文档只描述程序实际行为，不描述设计愿景。

## 1. 组成与运行模型

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `main.cpp` | 命令行分发、单实例、托盘启动、改名迁移 |
| 窗口探测 | `capture/window_detector.*` | 枚举顶层窗口、进程名、客户区矩形、DPI 感知 |
| 抓屏 | `capture/screen_capture.*` | BitBlt + DIB 段，按矩形取像素 |
| 鼠标钩子 | `capture/mouse_hook.*` | `WH_MOUSE_LL` 低级钩子，仅用于唤醒采样 |
| 白板识别 | `capture/whiteboard.*` | 品牌匹配、裁切标定 |
| 采集引擎 | `capture/capture_engine.*` | 采样循环、节流、状态切换、落盘调度 |
| 图像分析 | `analysis/frame_analyzer.*` | 灰度化、投影、ZNCC、位移估计 |
| 判定规则 | `analysis/keyframe_rules.*` | 纯函数：两帧关系判定与保存决策 |
| 会话 | `storage/session.*` | 会话目录、帧文件、`session.json` |
| 模型调用 | `ai/classifier.*` | OpenAI 兼容接口，逐帧判定 |
| 归档 | `ai/archiver.*` | 按日期/学科落盘，硬链接 |
| 流水线 | `ai/organizer.*` | 批量整理、断点续做、幂等 |
| 用量 | `ai/usage.*` | `usage.json` 账本 |
| 界面 | `app/tray_app.*` | 托盘菜单、设置对话框、定时整理 |

线程模型：界面与托盘在主线程；`CaptureEngine` 是独立 `QThread`，抓屏、分析、写盘都在该线程内完成，主线程不做像素处理。鼠标钩子回调运行在系统投递的上下文中，只更新状态标志，不执行业务逻辑。

采样节流：画面静止时按 `idle_interval_ms`（默认 1000 ms）取样，检测到变化后切到 `active_interval_ms`（默认 120 ms），持续 `active_hold_ms`（默认 3000 ms）无变化再退回。引擎维护抓屏耗时的移动平均 `m_avgCostMs`，当单次抓屏耗时超过采样周期的 35% 时自动放宽间隔，避免在低配机器上占满一个核。

前台约束：默认 `require_foreground=true`，仅当目标窗口位于前台且未被完全遮挡时采集；白板最小化、被全屏程序覆盖、屏幕锁定期间都暂停。`pause_on_extra_windows=true` 时，若目标窗口之上出现面积超过 `extra_window_min_w × extra_window_min_h` 的其他窗口（例如弹出的对话框），同样暂停，防止把弹窗当作板书存下来。

## 2. 关键帧判定

输入是 `GrayFrame`：缩放到 480 宽、按 `analysisCrop()` 裁掉工具栏后的灰度图，附带行/列投影、墨量 `inkLevel` 与面板占比 `solidRatio`。

`analyzePair()` 对「候选帧」与「当前帧」做一次判定，顺序固定：

1. 未位移相似度 `score00 ≥ same_threshold`（0.90）→ `Same`，画面没变。
2. 位移量 `max(|dx|,|dy|) > move_threshold`（3 px）且对齐后相似度 `score ≥ aligned_min_score`（0.50）→ `Shift`，整体平移。
3. `score00 < replace_threshold`（0.35）→ `Replace`，翻页或清屏。
4. 其余 → `Writing`，同屏继续书写。

顺序不能调换。稀疏笔画的画面只要错位几十像素，未位移相似度就会掉到很低，若先判 `Replace`，所有拖动都会被当成翻页。

`decideKeyframe()` 决定候选帧是否落盘，并在落盘前依次做四道过滤：

| 过滤 | 条件 | 目的 |
| --- | --- | --- |
| 空白 | `ink < empty_ink`（0.003） | 全空屏不入库 |
| 面板 | `solidRatio > panel_threshold`（0.02） | 拍到大块纯色 UI（图形选择、更多菜单、登录框）时丢弃 |
| 重复 | 与上一张已保存帧相似度 `> duplicate_score`（0.93） | 避免同一画面存两次 |
| 间隔 | 距上次保存 `< min_save_interval_ms`（1500） | 框选、缩放、连续翻页时不连拍 |

通过过滤后按关系决定：

- `Shift`：候选帧在平移期间不更新，`dx/dy` 即累计位移；累计位移超过画面高度的 `move_percent`（25%，且不少于 16 px）才保存，否则只累积不落盘。
- `Replace`：立即保存**候选帧**，即变化发生前的那一屏。
- `Same` / `Writing`：不保存，除非距候选帧已超过 `max_span_seconds`（180 秒），此时兜底保存一张。

因此「同屏写字」本身不产生截图，直到整屏被替换或超时。这是有意为之：候选帧持有的是「写满但尚未擦除」的完整画面，保存它比保存变化后的空白更有价值。

## 3. 白板识别与裁切标定

品牌匹配见 `whiteboard.h` 的 `kBrands` 表：进程名命中记 3 分，窗口标题命中记 2 分，总分 ≥ 2 才视为候选；多个候选时按「得分 + 是否前台 10 分」排序取最高。内置条目为希沃白板 5（`EasiNote.exe`）、希沃轻白板（`EasiNote5C.exe`）、鸿合（`HiteTouchPro.exe`）。未命中任何品牌时，若用户已指定 `target_process`，按指定进程采集，不做品牌判断。

裁切标定由 `BoardCalibrator` 完成：累计至少 30 帧、观察到至少 5 次画面变化后开始计算。判据是逐行均值的最小变化量

```
D[y] = min over frames | rowMean(y) - rowMean(y-1) |
```

工具栏区域在整节课里始终保持静止，`D[y]` 接近 0；板书区域不断变化，`D[y]` 明显偏大。据此确定上、下边界，按百分比向上取整；左右边界不标定，沿用配置。标定值按小写进程名存入 `board_calibrations`，与分辨率绑定。

裁切比例统一夹取到 `0–45%`，裁切后宽或高不足 64 px 时退回全局默认，避免配置被改坏后无法采集。

## 4. 存档结构

原始记录（`recordings`，路径由 `output_dir` 决定，默认为程序目录下 `recordings`）：

```
recordings/
└── 2026-11-04_190308/          会话目录，命名 yyyy-MM-dd_HHmmss，重名时追加 _1、_2
    ├── 190324.png              帧，命名 HHmmss.png，同秒冲突时追加 _1
    ├── 190343.png
    ├── session.json            帧清单
    └── organized.json          归档标记（整理成功后写入）
```

`session.json` 由 `QSaveFile` 原子写入，每保存一帧更新一次：

```json
{
  "started": "2026-11-04T19:03:08",
  "updated": "2026-11-04T19:42:11",
  "frame_count": 12,
  "frames": [
    { "file": "190324.png", "time": "2026-11-04T19:03:24", "reason": "画面大面积替换（未动相似度 0.21，对齐后也仅 0.24）" }
  ]
}
```

`reason` 记录判定原因，离线核对「为什么存了这一张」时以它为准。

归档结果（`板书笔记`，路径由 `ai_output_dir` 决定）：

```
板书笔记/
└── 2026-11-04/
    ├── 原图/190324.png        原始帧的硬链接，只写一次，之后只读
    ├── 数学/01_一元二次方程.png
    ├── 语文/01_未识别.png
    ├── 其他/                  未判出学科的帧
    └── index.json             日期索引（隐藏属性），供程序读取
```

学科目录内的文件名格式为 `<两位序号>_<知识点>.png`，序号在同一天、同一学科内连续编号，不按会话分段重启，保证按名称排序即上课顺序。时刻信息不进入文件名，保留在 `index.json` 的 `keyframes` 数组中。

硬链接优先，跨卷或文件系统不支持时退回复制。`原图/` 一旦写入不再修改或覆盖，任何重新归档都从它读取。

`organized.json` 与 `classify.json` 是幂等机制的基础：

| 文件 | 位置 | 内容 | 作用 |
| --- | --- | --- | --- |
| `organized.json` | 会话目录 | `organized_at`、`archive`、`frames` | 标记该会话已整理，且记录整理时的帧数 |
| `classify.json` | 会话目录 | 帧名 → `subject`、`subject_confidence`、`topic`、`topic_confidence`、`keywords` | 逐帧判定缓存，重跑不重复计费 |

判定「已整理」的条件是 `organized.frames ≥ 当前帧数`。录制中途整理过、之后又写了新内容的会话，会因帧数增加而被重新纳入整理，这正是 v0.15.1 修正的问题。

## 5. AI 归档流水线

```
未整理会话 → 逐帧分类（classify.json 缓存） → 归档（原图 + 学科目录 + index.json） → 写 organized.json
```

分类请求携带裁切后的 JPEG，长边不超过 `max_image_width`（1280），质量 85。请求体只包含图片与提示词，不包含窗口标题、进程名、文件路径与用户名。

错误分两类：

- **可重试**：超时、5xx、连接中断。按 `max_retries`（2）退避重试，仍失败则跳过该帧，继续后续帧。
- **致命**：Key 无效、余额不足、接口地址或模型名错误、模型不支持图像输入。立即停止整批，不写 `organized.json`，已判帧保留在 `classify.json`，问题解决后重跑从断点继续，不重复计费。

`usage.json` 按月分桶记录请求数、图像数、token 数与估算金额，保留 24 个月。缓存命中的帧不计入。

未配置 `ai_api_key` 时，分类器退化为全部返回「其他 / 未识别」，采集与归档仍可正常工作。

## 6. 配置项

配置位于程序目录的 `settings.json`，缺失时自动生成默认值。键名与默认值：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `target_process` | 空 | 目标进程名；留空按品牌表自动识别 |
| `idle_interval_ms` | 1000 | 静止采样间隔，范围 100–10000 |
| `active_interval_ms` | 120 | 变化后采样间隔，范围 50–5000 |
| `active_hold_ms` | 3000 | 变化后维持高频采样的时长 |
| `replace_threshold` | 0.35 | 整屏替换阈值，范围 0.05–0.95 |
| `same_threshold` | 0.90 | 判定「没变」的相似度，范围 0.05–0.999 |
| `move_threshold` | 3 | 判定平移的最小位移（缩略图像素），范围 2–500 |
| `move_percent` | 25.0 | 累计位移达到画面高度百分之多少才保存 |
| `max_span_seconds` | 180 | 持续书写的兜底保存间隔，范围 10–3600 |
| `output_dir` | 空 | 原始记录目录；空表示程序目录下 `recordings` |
| `ai_output_dir` | 空 | 归档目录；空表示程序目录下 `板书笔记` |
| `crop_top_percent` 等四项 | 5 / 23 / 0 / 0 | 全局默认裁切比例，按分辨率自适应 |
| `require_foreground` | true | 仅采集前台窗口 |
| `pause_on_extra_windows` | true | 目标窗口被遮挡时暂停 |
| `extra_window_min_w` / `_h` | 160 / 120 | 判定「遮挡窗口」的最小尺寸 |
| `pause_on_panel` | true | 出现 UI 面板时暂停 |
| `panel_threshold` | 0.02 | 面板占比阈值 |
| `empty_ink` | 0.003 | 空白判定阈值 |
| `start_on_launch` | false | 启动后自动开始采集 |
| `ai_base_url` | DashScope 兼容地址 | 模型接口 |
| `ai_api_key` | 空 | 为空则不启用 AI |
| `ai_model` | `qwen3-vl-flash` | 模型名 |
| `auto_organize` | false | 每日定时整理 |
| `auto_organize_hour` / `_minute` | 18 / 30 | 定时整理时刻 |
| `board_calibrations` | 空 | 按小写进程名保存的标定结果 |

外部修改导致越界的数值会被夹回合法范围，JSON 解析失败时整体回退默认值并在日志中告警。

## 7. 命令行

| 参数 | 说明 |
| --- | --- |
| `--info` | 打印 Qt 版本、DPI 模式、窗口枚举与自启状态后退出 |
| `--grab N [--interval MS] [--out DIR] [--fullscreen] [--region WxH]` | 连续抓 N 帧到目录，用于验证抓屏链路与带宽 |
| `--analyze DIR` | 离线回放截图目录，输出每帧的判定结果与最终保存数 |
| `--record N [--no-foreground]` | 无界面运行采集引擎 N 秒，验证完整链路 |
| `--watch N` | 监视目标窗口变化 N 秒，排查「弹窗被误截」 |
| `--classify [--session-dir DIR] [--archive DIR] [--reclassify]` | 整理未归档会话；`--reclassify` 忽略缓存重新调用模型 |
| `--organize-pending` | 手动触发定时整理所执行的同一流程 |
| `--ai-test IMAGE` | 用一张图自检模型可用性，报告失败原因 |
| `--organize-note SRC [--note-out DIR]` | 整理平铺的截图文件夹，按日期/学科归类并重命名 |
| `--show-settings` / `--reset-settings` | 直接打开设置界面 / 恢复出厂默认（保留 AI Key 与接口地址） |
| `--hook-bench [SECONDS]` | 测量鼠标钩子引入的输入延迟，输出 p50/p95 与结论 |

`--session` 不可用：Qt 的 `QApplication` 在解析前会吞掉 `--session` 及其值，故改用 `--session-dir`。

## 8. 部署与维护

批量部署：在一台机器完成配置后，退出程序，拷贝整个程序目录；不要携带 `recordings/` 与 `板书笔记/`。新机器首次运行需要重新标定，建议第一节课完整录制，标定在第 30 帧、第 5 次画面变化后生效。

存放位置：程序目录即数据目录，`settings.json`、`recordings/`、`板书笔记/`、`usage.json`、`BoardMark.log` 均在其中。放在启用还原卡的磁盘上会导致数据在重启后丢失；放在 `C:\Program Files` 会因权限问题无法写入配置。

开机自启：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不需要管理员权限。以管理员身份运行时写入的是管理员账户的注册表，普通登录不会触发；使用还原卡的机器同样可能失效，此时可在启动文件夹放置快捷方式。

迁移与升级：升级只替换可执行文件与 DLL，`settings.json` 与两张数据目录不受影响。迁移到新机器时复制 `settings.json` 可保留配置，但标定值与分辨率绑定，应清除后重新标定。

清理：`recordings/` 中旧会话可直接删除；`板书笔记/` 中是硬链接，删除原始记录不会连带删除归档，反之亦然。

## 9. 故障排查

| 现象 | 判定依据 | 处置 |
| --- | --- | --- |
| 托盘无图标 | `BoardMark.log` 最后一条记录；进程是否存在 | 检查安全软件拦截；确认没有已运行实例 |
| 有图标但不产生帧 | `--info` 是否列出目标窗口；会话目录是否有 `session.json` | 手动指定 `target_process`；确认白板在前台且未最小化 |
| 截图过多 | `session.json` 中 `reason` 多为「大面积替换」 | 提高 `replace_threshold`，或提高 `min_save_interval_ms` |
| 截图过少 | 会话帧数明显低于课时长度 / 20 分钟 | 降低 `replace_threshold`、降低 `same_threshold`、降低 `max_span_seconds` |
| 关键帧被裁掉半截 | 归档图中出现工具栏或缺失板书边缘 | 清除该进程的标定，重新完整录一节课 |
| 归档结果全是「其他」 | `classify.json` 中 `subject` 为「其他」；`usage.json` 是否有记录 | 核对 Key、余额、模型名；用 `--ai-test` 验证 |
| 归档中断 | 会话目录无 `organized.json` | 修复原因后重跑 `--classify`，已判帧走缓存 |
| 开机不启动 | `HKCU\...\Run` 下是否存在 `BoardMark` | 检查是否以管理员运行；改用启动文件夹 |
| 鼠标出现延迟 | `--hook-bench 8` 的 p95 | p95 > 4 ms 视为明显，需检查安全软件的钩子注入 |
| 程序无法启动 | 双击后无反应且无日志 | 检查是否缺 DLL；发布包应与 exe 同目录 |

## 10. 日志

`BoardMark.log` 位于程序目录，托盘模式启动时开始写入。启动、会话开始/结束、每次落盘、整理结果、模型调用失败都会记录；帧级判定原因在 `session.json` 的 `reason` 中，不在日志里。

反馈问题时需要提供：`--info` 输出、日志末 50 行、出问题那一屏的截图、白板软件名与分辨率/缩放。

## 11. 构建与发布

依赖：Qt 6.11+（Core、Gui、Widgets、Network）、MinGW-w64 g++ 13+ 或 MSVC 2019+、CMake 3.21+、Ninja。无第三方图像库。

```powershell
cmake -S . -B build -G Ninja `
  -DCMAKE_PREFIX_PATH=E:/Environment/mingw-w64/ucrt64 `
  -DCMAKE_BUILD_TYPE=Release
cmake --build build
windeployqt --release --no-translations build\BoardMark.exe
```

MinGW 构建附加 `-static -static-libgcc -static-libstdc++`。版本号在 `CMakeLists.txt` 的 `project(... VERSION ...)`，编译期注入为 `CM_VERSION`；构建日期注入为 `CM_BUILD_DATE`。发布包约 33 MB（zip），解压后约 85 MB，其中 `libicudt*.dll` 占约 32 MB。

## 12. 编码约定

- 含 `Q_OBJECT` 的类放在具名命名空间内，并在对应 `.cpp` 末尾 `#include "xxx.moc"`，否则 moc 产物不会链接。
- 中文字符串比较使用 `QStringLiteral`；`QLatin1String` 在此场景下会静默比较失败。
- `settings.json` 中路径等于默认值时写空串，避免程序搬迁后残留绝对路径。
- 原始帧只写一次；任何需要「重来」的场景都从 `原图/` 重新读取，不修改已有文件。
- 判定规则保持为纯函数（`analyzePair` / `decideKeyframe`），便于用 `--analyze` 离线验证与回归对比。

## 13. 已知限制

- 仅支持单显示器：采集目标窗口所在的那一块屏，跨屏窗口会被裁到单屏范围内。
- 不支持 Windows 7/8；依赖 Qt 6 与 DWM 的 DPI 接口。
- 无导出 PDF、无跨帧拼接。
- 学科判断依赖模型能力，长尾学科（如校本课程）会落入「其他」。
- 未做代码签名，安全软件可能拦截。
